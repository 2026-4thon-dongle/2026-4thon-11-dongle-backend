# docs/design

전반적인 설계와 설계 변경을 기록하는 공간이다. 결정 로그도 여기에 둔다.

## 문서 종류와 이름 규칙

| 종류 | 이름 | 용도 |
|---|---|---|
| 결정 로그 | `1105_log_decision-log.md` (저장소에 하나, 이름 고정) | 팀이 합의한 결정. **모든 문서 중 우선순위가 가장 높다** |
| 설계 묶음 | `MMDD_vNN_{이름}/` 폴더, 안의 문서는 `MMDD_vNN_{문서-이름}.md` | 전체 설계 (도메인, ERD, API, 디자인 시스템 등) |
| 변경 설계서 | `MMDD_{기준 커밋 짧은 해시 7자리}_{변경-이름}.md` | 기존 설계와 다르게 구현해야 할 때. 팀 합의 후 해당 항목에 한해 기존 설계보다 우선 |

- 설계 묶음을 크게 고쳐 새 버전을 만들 때는 버전을 올린 새 폴더(`v02`)를 만들고, 이전 묶음의 README 맨 위에 대체되었다고 적는다.
- 설계 묶음 폴더에는 묶음 안 문서 목록을 담은 README를 둔다(아래 양식).
- 설계 문서는 크기 때문에, 읽는 사람이 필요한 절만 찾을 수 있도록 절 제목을 구체적으로 쓴다.

## 우선순위

1. 결정 로그
2. 변경 설계서 (해당 항목에 한해)
3. 설계 묶음
4. 작업 설계 (`docs/work`)
5. PR 설명서 (`docs/PR`)

설계끼리 충돌하면 추측하지 말고 팀에 확인한다.

## 결정 로그 양식

결정 하나를 표 한 행으로 추가한다. 번호는 `D001`부터 차례로 붙이고 지우지 않는다. 결정을 뒤집으면 새 번호로 추가하고 이전 행의 상태를 「대체됨(Dxxx)」로 바꾼다.

```markdown
| 번호 | 날짜 | 결정 | 이유 | 관련 문서·PR | 상태 |
|---|---|---|---|---|---|
```

## 설계 묶음 README 양식

```markdown
# {설계 묶음 이름} vNN

- 작성일: YYYY-MM-DD
- 작성자:
- 상태: 초안 / 합의됨 / 대체됨(vNN)

## 범위

## 문서 목록

| 문서 | 내용 |
|---|---|
```

## 설계 문서 양식

```markdown
# {문서 제목}

- 작성일: YYYY-MM-DD
- 작성자:
- 설계 묶음: vNN
- 관련 결정:

## 배경

## 설계

## 대안과 선택 이유

## 미결 사항
```

## 변경 설계서 양식

```markdown
# {변경 이름}

- 작성일: YYYY-MM-DD
- 작성자:
- 기준 커밋:
- 바꾸는 설계: (설계 묶음·문서·절 이름)
- 합의: (합의한 사람·날짜, 합의 전이면 「합의 전」)

## 변경 이유

## 기존 설계

## 변경 내용

## 영향 범위

## 관련 PR
```
