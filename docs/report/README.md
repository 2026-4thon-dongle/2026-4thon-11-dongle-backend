# docs/report

사용자가 보고서를 요청하면 조사하고 그 내용을 **출처와 함께** 정리해 두는 공간이다. 테스트 데이터·테스트 계정 문서도 여기에 둔다.

## 이름 규칙

- 일반 보고서: `MMDD_{기준 커밋 짧은 해시 7자리}_{보고서-이름}.md`
- 특정 PR에 대한 보고서: `MMDD_PR{번호 3자리}_{보고서-이름}.md`
- 테스트 데이터 문서: `MMDD_{기준 커밋 짧은 해시 7자리}_test-data.md` (처음 만든 날짜·커밋으로 이름을 고정하고, 이후에는 같은 문서를 고친다)

## 보고서 규칙

- 출처와 **확인 날짜**를 반드시 남긴다.
- 확인한 사실과 추측·분석을 구분해서 쓴다.

## 보고서 양식

```markdown
# {보고서 제목}

- 작성일: YYYY-MM-DD
- 작성자:
- 기준 커밋 / 관련 PR:

## 요약

## 요청 내용

## 조사 범위와 방법

## 조사 결과

## 분석

## 결론과 권고

## 후속 작업

## 출처

| # | 출처 (제목, URL 또는 파일 경로) | 확인 날짜 |
|---|---|---|
```

## 테스트 데이터 문서 규칙

- 테스트 데이터나 테스트 계정을 만들면 그 단계 뒤에 이 문서를 남긴다.
- 데이터가 바뀌면 **같은 문서**를 고치고 맨 아래 변경 기록에 날짜·내용·PR을 남긴다. 요청하지 않아도 언제든 최신 내용을 볼 수 있어야 한다.
- 데이터를 바꾸는 PR은 PR 설명서 테스트 절에 이 문서의 갱신 여부를 적는다.
- 운영(배포) 환경의 실제 비밀번호나 비밀값은 적지 않는다. 테스트 전용 계정만 적는다.

## 테스트 데이터 문서 양식

```markdown
# 테스트 데이터

- 작성일: YYYY-MM-DD
- 최종 갱신: YYYY-MM-DD
- 적용 환경: (local / staging 등)
- 생성 방법: (fixture 경로, management command 등)

## 데이터 정보

| 대상 (model/table) | 건수 | 내용 |
|---|---|---|

## 테스트할 수 있는 기능

## 테스트 계정

| 역할 | 아이디 | 비밀번호 | 로그인 방식 |
|---|---|---|---|

## 변경 기록

| 날짜 | 내용 | PR |
|---|---|---|
```
