## 지금 작업 내용

기능명세서 1(AUTH)·2(DIARY)·7(SAFE)·8(SET)번의 백엔드 API를 구현한다.

## 목표

- 학교 메일 코드로 가입·로그인하고 JWT를 받는다.
- 일기를 작성·수정·삭제·조회한다.
- 신고·차단 결과가 `Diary.objects.visible_to(user)`에 반영된다.
- 마이 페이지, 지역·닉네임 수정, 알림 설정, 알림 센터를 쓸 수 있다.
- 위 동작을 `python manage.py test`로 확인한다.

## 범위

- 포함: 커스텀 User, 지역 마스터, 인증, 일기, 글감, 신고·차단, 연락처 감지, 마이·설정, 알림 목록·설정·푸시 토큰 저장
- 포함(연결에 필요한 최소): 우표 마스터와 지급 함수(No.01, No.02). 우표 API는 STAMP 담당 범위다.
- 제외: 피드(3), 편지(4), 우체통(5), 우표 API(6), 실제 푸시 발송(키와 제공자 미정), 배포 설정

## 참고한 상위 설계

- 결정 D001, D002
- 설계 묶음은 아직 없다. 기능 기준은 팀 기능명세서 1·2·7·8절이다.

## 작업 계획

1. 공통 에러 형식, 페이지네이션, JWT 설정
2. `regions`: 지역 마스터와 조회 API
3. `users`: 커스텀 User, `stamps`: 우표 지급
4. 인증 API (메일 코드, 가입, 로그인, 로그아웃)
5. `diaries`: 일기와 글감
6. `moderations`: 신고, 차단, 연락처 감지
7. 마이·설정, `notifications`: 알림 센터·푸시 토큰
8. 문서 레포의 `api/`·`spec/`·`changes/` 갱신

## 세부 설계

- 인증 코드는 해시로 저장한다. 6자리, 유효 5분, 시도 5회, 재발송 간격 60초.
- 가입은 메일 인증 → `signup_token`(서명 토큰, 30분) → 프로필 제출 순서다.
- 일기의 `region`은 작성 시점 거주지를 복사해 저장한다. 지역을 바꿔도 지난 일기는 바뀌지 않는다.
- 피드 담당은 `Diary.objects.visible_to(user)`로 차단·신고·공개 범위를 반영하고, 편지 담당은 `detect_contact_patterns`, `blocked_user_ids`, `notify`, `grant_stamp`를 쓴다.
- 편지 앱이 없어서 편지 수·펜팔 수·임시저장 수는 0을 돌려주고, 편지 신고는 `UNSUPPORTED_REPORT_TARGET`으로 막는다. 편지 앱이 생기면 연결한다.

## 결정·변경 사항과 남은 일

- 가정: 기획안과 기능명세서가 다르면 기능명세서를 따른다(담당자 지시).
- 가정: 응답 필드는 snake_case, URL prefix는 버전 없는 `/api/`. FE 합의 전이라 문서 레포에 초안으로 올린다.
- 가정: 지역 마스터는 17개 시·도와 228개 시·군·구로 넣고, 2026년 행정구역 개편은 반영하지 않는다.
- 가정: 신고 사유 코드는 Figma를 읽지 못해 임의로 정했다. 3-7 화면과 맞춰야 한다.
- 가정: 「같은 고향 사람」은 작성자와 본가 지역이 하나 이상 같은 사용자로 본다.
- 남은 일: 편지 앱 연결(받은 편지 수, 통계, 편지 신고), 실제 푸시 발송, `letter_paused` 적용(편지 담당), 배포 환경의 사진 저장소와 SMTP 설정.
