## 지금 작업 내용

시연 때 빈 화면 없이 피드·우체통·배송 중·우표첩을 보여 줄 수 있게, 시연용 계정과 데이터를 만드는 관리 명령 `seed_demo`를 만든다. 배포 서버에는 셸로 들어갈 수 없으므로 compose의 한 번짜리 서비스로 실행한다.

## 목표

- `python manage.py seed_demo`를 몇 번 실행해도 결과가 같다(시연 계정의 시연 데이터를 지우고 다시 만든다).
- 시연 계정이 아닌 사용자의 데이터는 만들거나 지우거나 고치지 않는다.
- 실행 직후 시연 계정 하나로 로그인하면 다음이 보인다: 내 지역 일기가 위에 오는 피드, 읽지 않은 새 편지, 주고받은 대화, 배송 중인 편지(경로 포함), 곧 도착할 편지, 우표 5개 이상(스티커·편지지 「밤하늘」 열림).
- `python manage.py seed_demo --remove`로 시연 데이터와 계정을 지운다.
- 배포 서버에서는 환경변수 `DEMO_SEED=true`일 때만 compose 서비스 `demo-seed`가 명령을 실행한다.

## 범위

- 포함: 관리 명령 `seed_demo`(`apps/users/management/commands/` 아래, 가정), 테스트, compose `demo-seed` 서비스, `.env.example`, README 「시연 준비」, `docs/report/` 테스트 데이터 문서
- 제외: 사진 업로드(일기는 글만), 손글씨 서명 이미지, 게임 관련 데이터(`apps/game/`, 게임 세션 소관), 운영 마무리(주간 글감 스케줄러·백업·Mailpit 헬스체크, 별도 작업)

## 참고한 상위 설계

- 문서 레포 `api/` 전체(응답에 쓰이는 모델), `spec/letter.md` 배송 구간
- `apps.letters.services.send_letter`, `apps.stamps.services.grant_stamps` — 데이터는 가능한 한 실제 서비스 함수로 만들어 API와 같은 규칙(구간, 우표, 출발 알림)을 따르게 한다.

## 작업 계획

1. 작업 설계 문서(이 문서)
2. `seed_demo` 명령: 계정·일기·편지·우표 생성, 다시 실행 시 초기화, `--remove`
3. 테스트: 두 번 실행해도 같은 건수, 시연 계정이 아닌 데이터 보존, 섞인 대화가 있으면 그 데이터는 건드리지 않음, `--remove`
4. compose `demo-seed` 서비스와 `.env.example`
5. README 「시연 준비」(데모 모드 켜고 끄기, 시연 데이터 만들기, 시연 확인 순서), `docs/report/` 테스트 데이터 문서
6. 검사·PR

## 세부 설계

- 시연 계정 식별: 메일 도메인 `@dongle-demo.ac.kr`(가정, 실제 학교 도메인이 아닌 이름). 다른 도메인 계정은 어떤 경우에도 대상이 아니다.
- 계정은 지우지 않고 그대로 두고(다시 실행해도 id가 바뀌지 않아 로그인 토큰이 유지된다), 내용만 지우고 다시 만든다. 로그인은 일반 사용자와 같이 메일 코드(Mailpit)로 한다.
- 초기화 때 지우는 것: 시연 계정끼리의 대화·편지, 시연 계정의 일기 중 다른 사용자와의 대화가 없는 것, 시연 계정의 우표·알림·임시저장·수집 보상 확인 기록.
- 안전장치
  - 시연 계정과 시연 계정이 아닌 사용자 사이의 대화가 있으면 그 대화와 그 대화가 달린 일기는 지우지 않고 건수만 알린다. `--remove`는 이런 대화가 있는 시연 계정을 지우지 않는다(지우면 상대의 편지가 함께 지워진다).
  - 시연 닉네임을 시연 계정이 아닌 사용자가 이미 쓰고 있으면 아무것도 바꾸지 않고 오류로 끝난다.
  - 전체를 한 트랜잭션으로 실행해 중간에 실패하면 아무것도 바뀌지 않는다.
- 데이터(계정 5개, 본가 → 거주)
  - 시연1 부산 → 서울 성북구 (시연 주인공), 시연2 서울 → 부산 해운대구, 시연3 제주 → 대전 유성구, 시연4 대구 → 광주 북구, 시연5 강원 → 서울 마포구
  - 일기: 계정마다 2개, 작성 시각을 지난 며칠에 나눠 둔다.
  - 편지: 시연2 → 시연1 도착·안 읽음 / 시연3 ↔ 시연1 왕복 완료 후 시연3의 다음 답장 배송 중 / 시연1 → 시연4 배송 중 / 시연4 → 시연1 몇 분 뒤 도착(`--arrive-in`, 기본 3분) / 시연5 → 시연2 도착·읽음
  - 배송 중 편지는 데모 모드와 관계없이 실제 구간 시간(1~12시간)으로 도착 시각을 둬서 시연 중에 도착하지 않게 한다. 지난 편지는 보낸 시각을 과거로 옮기고 도착 시각을 그에 맞춘다.
  - 우표: 서비스 함수가 주는 우표에 더해 시연1에게 꾸미기 우표 3개를 줘 보상(스티커, 「밤하늘」)이 열리게 한다.
