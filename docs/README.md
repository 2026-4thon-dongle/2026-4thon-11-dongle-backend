# docs

이 저장소의 협업 문서 공간이다. 설계, 작업 기록, PR 설명, 조사 보고서를 모두 여기에 둔다. 규칙의 요약은 루트 [CLAUDE.md](../CLAUDE.md)에 있다.

## 폴더

| 폴더 | 용도 |
|---|---|
| [design/](design/README.md) | 전체 설계와 설계 변경, 결정 로그 |
| [work/](work/README.md) | 경미하지 않은 개발 작업마다 쓰는 작은 설계와 진행 기록 (브랜치별) |
| [PR/](PR/README.md) | PR 하나에 폴더 하나. PR 설명서(정본)와 리뷰 기록 |
| [report/](report/README.md) | 요청받은 조사 보고서, 테스트 데이터·계정 문서 |

## 공통 이름 규칙

- 형식: `MMDD_{식별자}_{문서-이름}.md`
- `MMDD`: 한국 시간 작성일. 날짜가 항상 앞에 온다.
- `{식별자}`: 각 폴더 README가 정한다. 보통은 기준 커밋의 짧은 해시 7자리(예: `1002_a1b2c3d_mcp-sync-protocol.md`).
- PR 번호는 3자리로 쓴다. 모자라면 앞을 0으로 채우고 1000번부터는 그대로(예: `0924_PR002_login-page.md`). 본문에서는 PR47처럼 써도 되지만 이름은 반드시 3자리.
- 설계 묶음은 버전을 식별자로 쓴다(예: `1001_v01_{이름}/`).
- `{문서-이름}`: 그 문서를 특정할 수 있는 이름. 소문자 영문 kebab-case 권장, 한글 허용, 공백 금지.

## 양식 사용 원칙

- 문서를 쓰기 전에 그 폴더의 README를 먼저 읽고 양식의 구조를 지킨다.
- 양식은 문서의 구조를 정하는 기준이지 칸을 모두 채우라는 목록이 아니다.
  - 절 제목과 순서는 양식대로 지킨다.
  - 양식의 안내 문구나 예시 문장을 그대로 옮겨 쓰지 않고 실제 내용만 쓴다.
  - 분량은 내용에 맞추고, 표는 필요한 행만 둔다.
  - 해당 없는 절은 지우지 말고 「해당 없음」 한 줄만 쓴다.
- 양식을 바꿔야 하면 README부터 고친다.
- 새 문서 폴더를 만들면 그 폴더에도 용도·이름 규칙·양식을 담은 README를 함께 만든다.
- 문서는 한국어로 쓰되 테이블·API·코드 식별자는 영어로 쓴다.
